# The fight loop is written twice, on purpose

The round loop exists in two places: `FightEngine.runDueRounds` plays rounds as they fall due, and `Combat.simulate` plays a whole fight at once (for `EloSeason`, `TestFights.plant` and the balance tools). We keep both rather than extracting a shared stepper. The engine's copy is interleaved with persistence, events and the resume-after-outage logic, so only about six lines are shared, and a stepper would add a module without hiding anything. Drift between the two copies is caught by tests that run the real engine and compare every stored round and the outcome with `simulate` for the same seed: `FightEngineTests.theFightPlaysOutExactlyAsTheCombatCoreSimulatesItsSeed`, `ForcedFightTests.aForcedFightEndsAsItsSeedSays` and `OutageTests`. Keep those tests if either loop changes.
